# 사택 관리 시스템 (오프라인 프로토타입)

보안망 내 **완전 오프라인** 환경에서 동작하는 총무 담당자용 단일 HTML 프로그램입니다.
서버 없이 크롬/엣지에서 `index.html` 을 더블클릭해 바로 실행합니다.

## 실행 방법
1. `index.html` 을 크롬 또는 엣지로 엽니다. (파일 더블클릭)
2. 상단 우측 **데이터 폴더 선택** → 데이터를 저장할 폴더를 지정합니다.
3. 지정 폴더에 `sasys_data.json` 이 자동 생성되고, 모든 변경이 즉시 저장(축적)됩니다.
4. 다음 실행 시 이전 폴더가 자동 복원됩니다. (권한 만료 시 재선택 안내)

> 최초 실행 시 폴더를 지정하기 전에는 **샘플 데이터**가 화면 확인용으로 표시됩니다.
> 폴더를 지정하면 해당 폴더의 파일 내용으로 전환됩니다(비어 있으면 샘플이 기록됩니다).

## 데이터 저장
- **File System Access API** 사용 — 지정 폴더의 `sasys_data.json` 에 즉시 읽기/쓰기.
- 폴더 핸들은 IndexedDB 에 보관되어 재실행 시 복원됩니다.
- 미지원 브라우저(예: 구형/파이어폭스)에서는 **브라우저 로컬 저장(localStorage)** 으로 자동 폴백되며,
  화면 상단에 안내가 표시됩니다. 이 경우 **데이터 탭 → JSON 내보내기**로 정기 백업을 권장합니다.
- 별도 **JSON 내보내기/가져오기** 백업 버튼(데이터 탭)을 제공합니다.
- 첨부파일 저장 없음 — 텍스트 데이터만 관리합니다.

## PDF 자동 파싱 (번들 포함 — 바로 동작)
결재 PDF → 계약 데이터 자동 추출은 **pdf.js**(Mozilla, Apache-2.0)를 사용하며,
이 폴더에 **`pdf.min.js` 와 `pdf.worker.min.js` 가 함께 들어 있어 별도 설치 없이 바로 동작**합니다.
완전 오프라인 — 외부 CDN을 전혀 사용하지 않습니다.

- 신규 계약 등록 → **결재 PDF 업로드** 하면 자동 파싱되어 검토 폼에 채워집니다.
- 파일 직접 실행(file://) 시 브라우저의 Worker 제약이 있어도 메인스레드 폴백으로 동작하도록 처리돼 있습니다.
- 만약 `pdf.min.js` 가 없거나 로드에 실패하면 **대체안**이 자동 제공됩니다:
  **PDF 대신 텍스트 붙여넣기** → PDF 뷰어에서 텍스트 전체를 복사해 붙여넣으면 동일 파서로 채워집니다.

> 참고: 실제 결재 양식(사택신청)은 보증금·월세 표가 뒤엉켜 추출되고, 임대인 **연락처·계좌**
> 항목이 양식에 아예 없습니다. 파서가 금액/지급일/선·후불/소유주/지역(주소 기반)까지는
> 자동 인식하지만, **연락처·계좌는 계약서(첨부)를 보고 검토 폼에서 직접 입력**해야 합니다.

### 파싱 대상 라벨(고정 양식)
`센터명, 성명, 사번, 연고지 주소, 사택 주소, 계약구분(전/월세), 사용층, 전용면적,
소유주, 보증금 지급금액, 월세 지급금액, 월세 지급일, 문서번호, 결재선 마지막 결재일(→ 결재완료일)`

파싱 결과는 **즉시 저장되지 않고** 검토/수정 폼에 채워져 보여지며, 담당자 확인 후 저장됩니다.
파싱 실패 필드는 빈칸으로 두고 수동 입력할 수 있습니다.

## 화면 구성 (좌우 2분할 단일 화면)
- **상단 요약 스트립** — 전체/입주중/공실/이번달 월세/만료임박/정산중/미종결이슈. 숫자 클릭 시 좌측 목록 자동 필터.
- **왼쪽(목록)** — 사택 리스트 + 검색 + 상태 필터칩 + `＋신규 계약(PDF)`
- **오른쪽(선택 사택의 모든 것)** — 탭 이동 없이 한 화면에:
  - 진행상태 바(신청→계약중→해지예정→정산→반납완료) + 상황별 액션
  - **계약 변경(같은 회차 수정)** / **🔄 갱신(다음 회차 신규 생성)** / **해지** / **재계약**
  - 현재 계약(회차·임대인·연락처·계좌 포함) · 퇴실 정산 체크리스트 · 이슈 · 계약이력 · 변경이력
- **👤 직원 이력** (상단 버튼) — 직원별 누적 사용개월, 거쳐간 사택(회차 포함), 재직 중 이슈
- **⚙ 한도·데이터** (상단 버튼) — 지역·직급 한도표 편집, 폴더 지정, JSON 백업/복구

### 계약 변경 vs 갱신 (이력 관리)
- **변경**: 같은 계약(회차) 내에서 월세·입주자 정보 등을 수정 → 전/후 값이 변경이력에 자동 기록
- **갱신**: 기간 만료 후 이어갈 때. 기존 계약을 `갱신완료`로 닫고 **다음 회차(2회차, 3회차…)** 계약을 새로 생성 → 1회차/2회차 구분 및 이력 보존

## 데이터 모델(5계층)
`property → contract → settlement` / `issue` / `changelog(자동기록)`
자세한 필드는 `index.html` 상단 주석 및 `[STATE]` 섹션 참고.

## 참고
- 지역·직급 한도표는 프로토타입에서 **지역 기준**으로 판정하며, 직급 열을 추가해 세분화 확장이 가능합니다.
- 계약 수정 시 전/후 값이 `changelog` 에 자동 기록됩니다(필수 요건).
- 한도 초과 시 빨간 플래그가 표시되고 **초과 사유 입력이 강제**됩니다.
